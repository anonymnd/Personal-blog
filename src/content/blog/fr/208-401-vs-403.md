Imaginez que vous développez une application d'achats. Un utilisateur tente d'accéder au point de terminaison `/approve-request` et le serveur renvoie une erreur. Si vous utilisez 401 et 403 de manière interchangeable, votre frontend ne saura pas s'il doit rediriger l'utilisateur vers la page de connexion ou afficher un avertissement « Accès refusé ».

## La différence fondamentale
Le code HTTP 401 (Unauthorized) signifie en réalité « Non authentifié ». Il indique que le serveur ne sait pas qui est l'utilisateur. La requête manque d'identifiants valides ou le jeton a expiré. À l'inverse, le code HTTP 403 (Forbidden) signifie que le serveur sait exactement qui vous êtes, mais que vous n'avez tout simplement pas la permission d'accéder à cette ressource spécifique.

## Fonctionnement concret
Lorsqu'une requête arrive, le filtre de sécurité vérifie d'abord l'identité (Authentification). Si le JWT est absent ou si la signature est invalide, il renvoie un 401. Une fois l'identité confirmée, le serveur vérifie les rôles ou les permissions de l'utilisateur (Autorisation). Si un « Demandeur » tente d'accéder à une fonction réservée aux « Managers », le serveur renvoie un 403.

## Exemple concret : Flux d'achats
Considérons une requête vers `POST /orders/approve` :

1. **Scénario A** : L'utilisateur envoie la requête sans jeton Bearer.
   - **Résultat** : `401 Unauthorized`. Le serveur dit : « Je ne sais pas qui vous êtes ; veuillez vous connecter ».
2. **Scénario B** : L'utilisateur est connecté en tant que `REQUESTER` avec un jeton valide.
   - **Résultat** : `403 Forbidden`. Le serveur dit : « Je sais que vous êtes un Demandeur, mais seuls les Managers peuvent approuver les commandes ».

## Erreur courante : L'erreur générique
Une erreur fréquente consiste à renvoyer 403 pour tout ce qui touche à la sécurité. Si un jeton expire et que vous renvoyez 403, le frontend pourrait afficher « Vous n'avez pas la permission » au lieu de déclencher le flux de rafraîchissement du jeton ou la redirection vers la connexion.

## Exercice pratique
Quel code d'état doit être renvoyé si un utilisateur fournit un JWT valide mais tente de supprimer une demande d'achat appartenant à un autre département ?

**Réponse** : 403 Forbidden. L'utilisateur est authentifié, mais il n'est pas autorisé à modifier cette ressource spécifique.
