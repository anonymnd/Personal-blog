تخايل صاوبتي تطبيق ديال المشتريات (procurement app) فين الموظفين كيصيفطو طلبات. فالبداية، سيرفر واحد كان كافي وكلشي خدام مزيان. ولكن ملي كبرات الشركة، ولاو مئات الناس كيصيفطو طلبات فدقة وحدة. هنا السيرفر بدا كيتقال، والطلبات مابقاوش كيدوزو، وإذا طاح هاد السيرفر الوحيد، الخدمة كاملة كتحبس. هاد المشكل كيتسمى "Single Point of Failure".

## الفرق بين Scaling Out و Scaling Up
ملي السيرفر كيولي تقيل، تقدر تزيد ليه RAM أو CPU (هذا هو Vertical Scaling)، ولكن كاين واحد الحد فين مابقاش تقدر تزيد. الحل هو تخدم بزاف ديال النسخ من التطبيق (Horizontal Scaling)، يعني تفرق الخدمة على بزاف ديال السيرفرات صغار. هكذا، يلا طاحت شي نسخة، لخرين كيبقاو خدامين والخدمة مكاتحبسش.

## الدور ديال الـ Load Balancer
باش هاد النسخ يخدمو مجموعين، خاصنا Load Balancer. هو اللي كيكون بحال "بوليصي" ديال الطريق، كيشد الطلبات (HTTP requests) وكيفرقهم على النسخ اللي خدامين. كاينين طرق باش يفرقهم، مثلاً Round Robin اللي كيدوز عليهم بالترتيب، أو Least Connections اللي كيصيفط الطلب للسيرفر اللي عليه الضغط قليل.

## مشكل الـ Shared State
واحد الحاجة مهمة هي أن النسخ خاصهم يكونو "stateless". مثلاً، يلا الموظف صيفط ملف لـ Instance A، والمدير بغى يوافق عليه من Instance B، هاد Instance B ماراديش يلقى الملف يلا كان مخبي غير فالسيرفر A. داكشي علاش خاص المعلومات تكون فبلاصة مشتركة، بحال Database أو Cache بحال Redis.

## مثال تطبيقي: الموافقة على الطلبات
شوفو هاد السيناريو:
1. **الموظف** كيصيفط POST `/request` → Load Balancer → **Instance 1**. هاد النسخة كتحط الطلب فـ PostgreSQL DB مشتركة.
2. **المدير** كيصيفط GET `/pending` → Load Balancer → **Instance 2**. هاد النسخة كتجبد المعلومات من نفس الـ PostgreSQL DB.

**النتيجة:** السيستيم كيبقى خدام واخا Instance 1 يوقع فيه مشكل فاش كيكون المدير كيراجع الطلبات.

## غلط شائع: الـ Local Sessions
بزاف ديال المبرمجين كيخزنو session ديال المستخدم فالميموار ديال السيرفر (`HttpSession` فـ Jakarta EE). فاش كيكون عندك بزاف ديال النسخ، المستخدم يقدر يدخل لـ Instance 1، ولكن الطلب الجاي يمشي لـ Instance 2، تما السيستيم غيقول ليه راك ماشي connected.
**التصحيح:** خاص تستعمل distributed session store أو JWT باش أي نسخة تقدر تعرف شكون هو المستخدم.
