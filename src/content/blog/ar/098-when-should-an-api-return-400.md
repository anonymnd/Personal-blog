هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخايل معايا خدام على تطبيق ديال المشتريات (Procurement app). واحد الموظف صيفط طلب شراء، ولكن السيرفر رفضوا. واش الـ API خاصها ترجع 400 Bad Request ولا 422 Unprocessable Entity؟ بزاف ديال المطورين كيستعملو 400 لكلشي، وهذا كيخلي الكليان ميعرفش واش المشكل في شكل الـ JSON ولا في المعنى ديال البيانات.

## الدور ديال 400 Bad Request
الكود 400 كيعني أن السيرفر مقدرش يعالج الطلب حيت كاين غلط من جهة الكليان. هادشي كيتعلق بالضبط بـ *السانتاكس* (Syntax) أو *الشكل* ديال الطلب. مثلاً، إلا كان الـ JSON مخربق، أو شي حقل ضروري ناقص، أو صيفطتي نص (String) في بلاصة رقم (Integer)، هنا 400 هي اللي صحيحة.

## الفرق بين Validation ديال الدخل و Business Logic
خاصنا نفرقو بين شكل البيانات (Input shape) وبين واش ديك البيانات مقبولة في البيزنس. مثلاً، باستعمال Jakarta Bean Validation، `@NotNull` كتشوف واش الحقل كاين، و `@NotBlank` كتشوف واش النص ماشي خاوي. هادو كيتسماو structural checks. ولكن، باش تشوف واش الموظف عندو ميزانية كافية للشراء، هادي *قاعدة بيزنس* (Business rule). واخا البعض كيستعمل 400، ولكن 422 كتكون أدق فهاد الحالة.

## مثال تطبيقي: طلب شراء
نشوفو هاد الكود ديال طلب شراء:

```java
public class PurchaseRequest {
    @NotBlank
    private String itemDescription;
    
    @NotNull
    @Min(1)
    private Integer quantity;
}
```

إلا صيفط الكليان `{"quantity": 0}`، هنا `@Min(1)` غادي تعطي غلط. الـ API خاصها ترجع **400 Bad Request** حيت الدخل مكيحترمش العقد الأساسي. ولكن إلا صيفط طلب صحيح ولكن السلعة ممنوعة في الشركة، هادي غلط ديال الدومين ماشي 400.

## غلط شائع: الاعتماد فقط على @Valid
بزاف كيصحاب ليهم `@Valid` كتحمي من كاع البيانات الغالطة. `@Valid` غير كتفعل الـ validation، ولكن مكاتعوضش الـ unique constraints ديال لاباز دو دوني. مثلاً، إلا جوج ناس صيفطو نفس الـ ID في دقة وحدة، الـ validation غادي تدوز، ولكن لاباز غادي تعطي غلط. خاصك تعامل مع هاد exception باش مترجعش 500 Internal Server Error.

## تمرين تطبيقي
سيناريو: كليان صيفط JSON فيه التاريخ مكتوب "5 يناير" في بلاصة "2024-01-05". شنو هو الكود اللي خاص الـ API ترجع؟

**الجواب:** 400 Bad Request، حيت الفورما ديال البيانات (Syntax) غلط بالنسبة للنوع اللي كنتسناو.
