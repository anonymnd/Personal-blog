هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل راسك خدام على تطبيق ديال الشراء (procurement app). دوزتي تلت سوايع باش تقاد واحد الـ logic فين المدير كيوافق على الطلب. فجأة، بغيتي تزيد ميزة باش المشتري يكوموندي السلعة، ولكن غلطتي وهرستي داكشي لي صاوبتي ديال الموافقة. إلا كان عندك غير backup (مثلا ملف ZIP ديال البارح)، خاصك تمسح كلشي وتخسر دوك تلت سوايع، ولا تبقى تقلب على الغلط سطر بسطر فمئات السطور ديال الكود.

## الفرق بين Backup و VCS
الـ backup هو غير تصويرة (snapshot) ديال الملفات فواحد الوقت معين. ولكن VCS بحال Git هو تاريخ حي. الـ backup كيقول ليك الكود كيفاش كان نهار الثلاث، ولكن Git كيقول ليك شكون بالضبط لي بدل السطر 42، وعلاش بدلو، وكيخليك ترجع لديك الحالة بالضبط بلا ما تقيس الملفات لخرين.

## الـ Branching باش تجرب بلا خوف
فالتطبيق ديال الشراء، تقدر تبغي تجرب واحد الـ logic ديال "الموافقة التلقائية". بلا ما تخاطر بالكود لي خدام، كدير Branch (فرع). هادي بحال نسخة موازية من المشروع. تقدر تزيد تغييرات، وتفشل، ومن بعد تمسح داك الـ branch وترجع للكود لي كان خدام. هاد العزل مستحيل ديرو غير بـ backup عادي.

## مثال تطبيقي: تعديل الموافقة
نفترضو عندك ملف سميتو `ApprovalService.java`:
```java
public class ApprovalService {
    public boolean approve(Request req) {
        return req.getAmount() < 1000; // logic القديمة
    }
}
```
درتي branch سميتو `feature/manager-limit` وبدلتي الحد لـ 5000. إلا قال ليك المدير بلي هادشي بزاف، ما كترجعش backup كامل؛ كدير غير `git merge` للتغييرات ولا كترجع (revert) غير داك الـ commit لي غلطتي فيه. النتيجة هي أنك عندك سجل واضح ديال كل قرار تخاذ فلكود.

## غلط شائع: فخ ديال 'Final_v2_ActualFinal'
بزاف ديال المبتدئين كيسيفيو الملفات بحال `App_v1.zip` و `App_v2.zip`. الغلط هنا هو كيسحاب ليهم بلي هادشي كيتتبع التغييرات. لا، هادشي كيسيفي غير النسخ. التصحيح: خدم بـ `git commit -m "Update approval limit to 5000"`. هكا كتربط التغيير بسببه الحقيقي.

## تمرين تطبيقي
إلا مسحتي واحد الـ method مهمة فالتطبيق ديالك ودرتي ليها commit، شنو هي الـ commande ديال Git لي كتخليك تشوف التاريخ ديال داك الملف باش تلقى الكود لي تمسح؟

**الجواب:** `git log -p` ولا `git blame` باش تشوف كيفاش تطور الملف.
