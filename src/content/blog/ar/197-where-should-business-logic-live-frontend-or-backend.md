هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل كتصاوب تطبيق ديال الشراء (procurement app) فين الموظف كيصيفط طلب شراء. درتي قاعدة كتقول: « أي طلب فايت 1000 دولار خاصو موافقة ديال manager ». طبقتي هاد الشي في الـ frontend باش تطلع ميساج للمستخدم. ولكن، واحد المستخدم مطور حل الـ console ديال browser وصيفط request API نيشان فيها 5000 دولار، وهكا داز من فوق الـ UI ديالك. السيرفر قبل الطلب حيت ما كانش فيه التحقق. هادي هي المشكلة اللي كيوقع فيها بزاف ديال المطورين.

## الدور ديال Frontend Logic
المنطق ديال الـ frontend كاين أساساً باش يحسن تجربة المستخدم (UX). الهدف ديالو هو يعطي رد فعل سريع. مثلاً، ملي كتأكد واش الـ email مكتوب صحيح ولا واش كاين شي خانة خاوية قبل ما يورك المستخدم على 'Submit'، هنا راك خدام بـ frontend logic. هاد الشي كيخلي التطبيق يبان خفيف وكيقلل الـ requests اللي كيمشيو للسيرفر. ولكن، حيت الـ browser كيكون تحت تحكم المستخدم، أي حاجة تدار هنا تقدر تتبدل ولا يتم تجاوزها.

## علاش Backend Logic ضروري
الـ backend هو « مصدر الحقيقة » (Source of Truth). هو اللي مسؤول على السيكيريتي، سلامة البيانات، والقواعد ديال البيزنس. كيفما كان داكشي اللي صيفط الـ frontend، السيرفر خاصو يعاود يتأكد. في التطبيق ديالنا، السيرفر خاصو يشوف شحال هو المبلغ واش المستخدم عندو الحق يصيفطو قبل ما يسجلو في الـ database. هاد الشي ضروري حيت السيرفر هو البلاصة الوحيدة اللي المطور كيتحكم فيها 100%.

## مثال تطبيقي: نظام الموافقة
نشوفو كيفاش كنقسمو الخدمة في طلب شراء. الـ frontend كيدير الخدمة « البصرية » والـ backend كيدير الخدمة « القانونية ».

**Frontend (مثال بسيط):**
```javascript
if (requestAmount > 1000) {
  showNotification("هاد الطلب خاصو موافقة ديال manager");
}
```
**Backend (مثال Jakarta EE):**
```java
public Response processRequest(PurchaseRequest req) {
    if (req.getAmount() > 1000 && !req.isManagerApproved()) {
        return Response.status(403).entity("Approval required").build();
    }
    return service.save(req);
}
```
**النتيجة:** المستخدم كيشوف تنبيه مفيد في الواجهة، وفي نفس الوقت السيستيم كيبقى محمي حتى لو شي حد حاول يهرب من الـ UI.

## غلط شائع: تيق في الـ Client
بزاف كيديرو حسابات معقدة (بحال تخفيض في الثمن) غير في الـ frontend ويصيفطو الثمن النهائي للسيرفر. هنا المستخدم يقدر يبدل الثمن لـ 0.01 دولار في الـ request body.

**التصحيح:** صيفط غير الـ ID ديال المنتج والكمية. وخلي السيرفر هو اللي يحسب الثمن بناءً على الأثمنة اللي كاينين في الـ database.

## تمرين تطبيقي
سيناريو: المستخدم خاص يكون عندو 18 عام باش يتسجل. فين خاص نديرو هاد التحقق؟

**الجواب:** في بجوج. Frontend باش تكون UX مزيانة (ميساج ديال خطأ سريع)، و Backend باش تمنع أي تسجيل غير قانوني عن طريق أدوات الـ API.
