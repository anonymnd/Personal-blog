هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل راسك خدام على تطبيق ديال المشتريات (procurement app). الشاف ديالك جا يسولك فين وصلتي، ونت ورّيتيه schéma ديال database ناضية و API endpoints كيرجعو JSON خاوي. الشاف غادي يتفقص حيت مازال ما يقدر يدير حتى حاجة بالتطبيق. هذا هو الفخ ديال 'horizontal slicing'، فين كاتبني كاع الطبقات ديال data، ومن بعد كاع الطبقات ديال service، وعاد فالاخير كتفكر فـ الواجهة (UI).

## الفكرة ديال الـ Vertical Slice

الـ Vertical Slice هي واحد الطريقة فين كتخدم على ميزة (feature) وحدة صغيرة ولكن كاملة من لول حتى للخر. بلاصة ما تبني الساس كامل فدقة وحدة، كتقطع واحد 'طريف' رقيق كيدوز من كاع الطبقات: الواجهة، المنطق ديال البيزنس (business logic)، و بلاصة فين كتخزن الداتا. الهدف هو تخرج شي حاجة خدامة كتعطي قيمة حقيقية، باش تجرب واش الـ architecture لي درتي صحيحة ولا لا.

## كيفاش نطبقوها فـ تطبيق المشتريات

بلاصة ما تبني السيستيم كامل ديال 'تسيير المستخدمين'، بدا بواحد النتيجة محددة: "الموظف يقدر يصيفط طلب شراء".

**قواعد البيزنس (Business Rules):**
- الطلب خاص يكون فيه سمية السلعة والكمية.
- الحالة ديال الطلب كتبدا بـ 'Pending' (في الانتظار).

**معايير القبول (Acceptance Criteria):**
- المستخدم يعمر الفورميلير ويورك على 'Submit'.
- الداتا تسجل فـ database.
- تطلع ميساج ديال النجاح فـ الشاشة.

## مثال تطبيقي: صيفط طلب شراء

إلا كنا خدامين بـ Jakarta EE، الـ vertical slice ديال هاد الميزة غاتكون بحال هاد الكود (مثال توضيحي):

```java
@Path("/requests")
public class RequestResource {
    @Inject RequestService service;

    @POST
    public Response submitRequest(PurchaseRequest req) {
        service.save(req); // هنا كانديرو الحالة 'Pending'
        return Response.ok("Request Submitted").build();
    }
}
```

النتيجة: دابا الموظف يقدر يصيفط طلب. هكدا تأكدتي بلي الـ API والـ service والـ database كيهضرو مع بعضياتهم مزيان.

## غلط شائع: فخ 'الساس هو الأول'

بزاف ديال المطورين كيضيعو سيمانات باش يقادو generic repository pattern ولا global error handler قبل ما يديرو أول ميزة خدامة.

**التصحيح:** دير أبسط طريق ممكنة لأول slice. إلا حتاجيتي repository، دير واحد بسيط. ومن بعد ما تدير 3 ولا 4 ديال الـ slices، تما عاد تقدر ترجعهم generic حيت غاتكون عرفتي شنو لي كيتعاود.

## تمرين تطبيقي

**السيناريو:** بغيتي تزيد ميزة 'موافقة المدير' (Manager Approval) فـ التطبيق. حدد كيفاش غاتكون الـ vertical slice ديالها.

**الجواب:** خاص الجواب ديالك يكون فيه حركة فـ الواجهة (مثلا: يورك على بوطون 'Approve')، قاعدة بيزنس (مثلا: الحالة تولي 'Approved')، وتغيير فـ الداتا (تحديث السطر فـ database).
