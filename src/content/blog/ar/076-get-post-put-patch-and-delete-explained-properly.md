تخايل راسك خدام على تطبيق ديال الشراء (procurement app). عندك طلب ديال بيسي جديد، ولكن ماعرفتيش واش تستعمل PUT ولا PATCH باش تبدل الكمية، ولا واش POST هي الطريقة الوحيدة باش تكريه هاد الطلب. إلا غلطتي فـ الاختيار، الـ API ديالك غتولي ماكايناش فيها الدقة وغتوقع مشاكل فـ الـ caching ولا فاش السيستيم كيعاود يصيفط الطلب (retry).

## القراءة والإنشاء: GET و POST
`GET` كنستعملوها باش نجيبو المعلومات. كتسمى "safe" حيت ما خاصهاش تبدل والو فـ السيرفر. وهي أيضا "idempotent"، يعني واخا تعيط ليها 10 دالمرات، النتيجة غتبقى هي هي. أما `POST` فغالباً كنستعملوها باش نكريهو (create) حاجة جديدة. POST ماشي safe وماشي idempotent، حيت إلا صيفطتي نفس الطلب جوج مرات، غالباً غتكريه جوج ديال السجلات متشابهين.

## التعديل: PUT ضد PATCH
`PUT` كتصلح باش تعوض الحاجة كاملة (replacement). إلا بغيتي تعدل طلب شراء بـ PUT، خاصك تصيفط الـ object كامل. إلا نسيتي شي field، السيرفر يقدر يرجعو null. هي idempotent حيت تعويض نفس البيانات بزاف دالمرات ما كيغيرش الحالة النهائية. `PATCH` مديورة للتعديلات الجزئية (partial updates). كتصيفط غير داكشي لي بغيتي تبدل (مثلاً غير الحالة/status). PATCH ماشي بالضرورة تكون idempotent حيت كاينين عمليات (بحال زيادة +1) لي كيغيرو الحالة فكل مرة.

## المسح: DELETE
`DELETE` كتمسح resource. هي idempotent من ناحية الحالة ديال السيرفر: ملي كتمسح الحاجة، كتبقى ممسوحة. ولكن، الـ response code يقدر يتبدل (مرة الأولى 204 No Content، ومن بعد 404 Not Found)، ولكن النتيجة النهائية فـ السيرفر وحدة.

## مثال تطبيقي: طلب شراء

| العملية | الطريقة | الرابط (Endpoint) | البيانات | النتيجة المتوقعة |
| :--- | :--- | :--- | :--- | :--- |
| شوف الطلب | GET | `/requests/123` | والو | 200 OK + JSON |
| كـري طلب | POST | `/requests` | `{ "item": "Laptop" }` | 201 Created |
| عوض الطلب | PUT | `/requests/123` | `{ "item": "MacBook", "qty": 1 }` | 200 OK |
| بدل الحالة | PATCH | `/requests/123` | `{ "status": "Approved" }` | 200 OK |
| مسح الطلب | DELETE | `/requests/123` | والو | 204 No Content |

## غلط شائع: استعمال POST فكلشي
بزاف ديال المطورين كيستعملو POST حتى فالتعديل حيت جاتهم ساهلة. ولكن هادشي كيخالف قواعد REST. إلا كان شي مشكل فـ الريزو والـ client عاود صيفط POST، يقدر يكريه طلبات مكررة. استعمال PUT فالتعديل كيخلي الـ retries يكونو آمنين.

## تمرين تطبيقي
أنا طريقة خاصك تستعمل باش تبدل غير العنوان ديال التوصيل فـ طلب موجود، بلا ما تصيفط كاع المعلومات الأخرى ديال الطلب؟

**الجواب:** `PATCH` حيت هي لي مديورة للتعديلات الجزئية.
