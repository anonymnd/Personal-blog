هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل راسك خدام على تطبيق ديال المشتريات (procurement app). الشيف ديالك قال ليك: "غير رئيس القسم اللي يقدر يوافق على طلبات اللي فايتة 5000 دولار". نتا ديريكت مشيتي كتبتي `if` فـ Java controller. ولكن بلاتي، واش عرفتي شنو غيوقع يلا الشركة بدلات هاد المبلغ لـ 7000 دولار الشهر الجاي؟ يلا خلطتي "علاش" (قانون البيزنس) مع "كيفاش" (التقنية)، الكود ديالك غيولي معقد وصعيب تبدلو.

## شنو هما قواعد البيزنس (Business Rules)
قواعد البيزنس هما القوانين اللي كتمشى بها الشركة، سواء كان كاين كمبيوتر ولا لا. هي اللي كتشرح كيفاش كيدوز الدومين. مثلا فالتطبيق ديالنا، قاعدة بحال "لي طلب السلعة ما يمكنش يوافق على الطلب ديالو راسو" هي Business Rule. هادي قاعدة ديال الحماية من التزوير، وكيكونوا محددين من طرف الناس اللي كيسيروا المشروع (actors).

## شنو هما القواعد التقنية (Technical Rules)
القواعد التقنية هما قيود مفروضة من طرف التكنولوجيا اللي خدام بها أو لـ architecture ديال السيستيم. هادو ما كيهمهومش الربح ولا قانون الشركة، كيهمهوم غير السيستيم ما يطيحش. مثلا: "الوصف ديال الطلب خاصو يكون UTF-8 وما يفوتش 2000 حرف" أو "الـ API خاصها تجاوب فقل من 200ms". هادو كيتسماو non-functional constraints.

## مثال تطبيقي: مسار الموافقة
نشوفو مثال ديال طلب شراء:

**قاعدة بيزنس:** الطلب خاص يوافق عليه Manager يلا كان الثمن فايت 1000 دولار.
**قاعدة تقنية:** التاريخ ديال الموافقة `approvalDate` خاصو يتسجل بصيغة ISO-8601 فـ database.

```java
// مثال توضيحي: كيفاش نفرقو بيناتهم
public class ProcurementService {
    public void processRequest(Request req, User user) {
        // Business Rule: واش عندو الحق يوافق؟
        if (req.getAmount() > 1000 && !user.hasRole("MANAGER")) {
            throw new UnauthorizedException("خاص موافقة manager");
        }
        // Technical Rule: واش الداتا صحيحة؟
        if (req.getDescription() == null) {
            throw new ValidationException("الوصف ضروري");
        }
    }
}
```

## غلط شائع: كودينغ ديال القوانين (Hardcoding)
بزاف ديال المطورين كيديرو قوانين البيزنس وسط الـ UI (مثلا فـ JavaScript). يلا درتي شرط "1000 دولار" غير فـ frontend، أي واحد كيعرف شوية يقدر يتجاوزو عن طريق API. الحل هو أن Business Rules يكونوا فـ Domain layer، و Technical Rules يكونوا فـ Infrastructure أو Validation layer.

## تمرين تطبيقي
قول ليا شكون فيهم Business Rule وشكون Technical Rule:
1. "السيستيم خاصو يتحمل 500 مستخدم فدقة وحدة."
2. "المشتري ما يمكنش يشري من عند مورد (vendor) محظور."

**الجواب:** 1 تقنية (Performance)؛ 2 بيزنس (Politique d'achat).
