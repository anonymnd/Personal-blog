هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

كتكون عندك فكرة واعرة ديال تطبيق، ولكن كتبقى حاير واش تبدا بـ database schema ولا بـ UI layout. هاد الحيرة عادية، ولكن الغلط اللي كيديرو بزاف ديال المبتدئين هو كيبغيو يرسمو l'architecture ديال السيستيم كامل قبل ما يكتبو سطر واحد ديال الكود، وهادشي كيخليهم يضيعو الوقت فـ features اللي يقدر المستخدم ما يحتاجهمش أصلاً.

## بدا بالنتيجة اللي بغا المستخدم (User Outcome)
قبل ما تفكر فـ التكنولوجيا، حدد شنو هو الهدف الأساسي. بلاصت ما تقول "بغيت ندير سيستيم ديال المشتريات"، قول "الموظف يقدر يصيفط طلب شراء والمدير يقدر يوافق عليه". هكا كتولي مركز على القيمة اللي كيعطي التطبيق. من بعد، حدد القواعد ديال البيزنس (Business Rules)، مثلاً: "أي طلب فات 1,000 درهم خاصو موافقة ديال جوج مديرين".

## حدد "طريف" خدام (Vertical Slice)
بلاصت ما تبني كاع الـ User Management بوحدها ومن بعد الـ Database بوحدها، دير vertical slice. يعني دير مسار صغير خدام من الفوق لتحت. فـ تطبيق المشتريات، هاد الطريف يكون هو: الموظف كيعمر فورمير → الداتا كتمشي لـ DB → المدير كيشوف الطلب. هكا كتعرف واش الخطة ديالك خدامة تقنياً دابا.

## حدد شروط القبول (Acceptance Criteria)
شروط القبول هي اللي كتقول ليك بلي هاد الميزة سالات. باش ما تبقاش تزيد فـ الخدمة بلا فايدة، حدد شروط بحال: 
1. السيستيم ما يقبلش طلب خاوي من سمية المنتج.
2. الحالة (Status) تولي 'Approved' ملي المدير يورك على موافق.

## مثال تطبيقي
ها كيفاش كنحولوا قاعدة ديال البيزنس لكود (مثال بسيط بـ Jakarta EE) :

```java
// مثال توضيحي: منطق الموافقة على الطلب
public class ProcurementService {
    public void approveRequest(Long requestId, User manager) {
        Request req = repository.findById(requestId);
        if (req.getAmount() > 1000 && !manager.isSeniorLevel()) {
            throw new UnauthorizedException("خاص موافقة مدير كبير");
        }
        req.setStatus(Status.APPROVED);
        repository.save(req);
    }
}
```

## غلط شائع: فخ الـ Architecture
بزاف ديال المطورين كيضيعو سيمانات وهوما كيقلبو على "أحسن" database قبل ما يجربو واش الفكرة أصلاً خدامة. **التصحيح:** بدا بـ structure بسيطة (Monolith). الـ Architecture خاصها تكون تطورية، يعني بدلها غير ملي تحس بلي السيستيم بدا كيتقال ولا مابقاش كافي.

## تمرين تطبيقي
**السيناريو:** بغيتي تصاوب تطبيق بسيط ديال تتبع المهام (Task Tracker). حدد vertical slice وحدة وجوج ديال شروط القبول.

**الجواب:** الـ slice تكون هي "كتابة مهمة جديدة وشوفها فـ القائمة". الشروط: 1. المهمة خاص يكون عندها عنوان. 2. المهمة تبان فـ القائمة مباشرة مورا ما تسجل.
