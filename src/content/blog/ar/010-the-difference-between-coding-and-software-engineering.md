هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل معايا بغيتي تصاوب تطبيق ديال المشتريات (procurement app) فين الموظف كيصيفط طلب والمير (manager) كيوافق عليه. اللي كيدير غير 'الكودينغ' كيركز باش يخلي Bouton 'Submit' يخدم والبيانات تسجل. ولكن مهندس البرمجيات كيسول: 'وإلا كان المير في كونجي شنو غيوقع؟' ولا 'كيفاش غنديرو إلا تبدلو شروط الموافقة العام الجاي؟'

## الكودينغ: عملية التنفيذ
الكودينغ هو فاش كتحول منطق معين للغة كيفهمها الكمبيوتر. هنا كيكون التركيز على السانتاكس (syntax)، الخوارزميات، وباش الحاجة تخدم دابا. إلا قدرتي تكتب فنكشن كتحسب المجموع ديال الطلبية، راك كدير الكودينغ. هادي مهارة ضرورية، ولكنها مجرد أداة ماشي هي العملية كاملة.

## هندسة البرمجيات: نظرة شاملة
هندسة البرمجيات هي فاش كنطبقو قواعد الهندسة على البرمجة. كتركز على دورة الحياة كاملة: المتطلبات، واش السيستيم يقدر يكبر (scalability)، وكيفاش نبقاو نصلحوه بلا ما نخسروه (maintainability). الكودينغ كيسول 'كيفاش' نطبق الميزة، ولكن الهندسة كتسول 'شنو' خاصنا نبنيو، 'علاش' بهاد الطريقة، وكيفاش غيتطور السيستيم مع الوقت.

## مثال تطبيقي: نظام المشتريات
ناخدو طرف صغير من السيستيم:

**قاعدة العمل:** أي طلب فايت 1000 دولار خاصو موافقة ديال Senior Manager.
**شروط القبول:** السيستيم خاصو يمنع حالة 'Commande' حتى تاخد الموافقة من الدور (role) المطلوب.

*طريقة الكودينغ:* كيدير غير `if (amount > 1000) { requireApproval(); }` وسط الكود.
*طريقة الهندسة:* كيصاوب `ApprovalStrategy` interface. هكذا إلا بغات الشركة تزيد مستوى جديد (مثلا Director)، مكنحتاجوش نعاودو نكتبو الكود كامل.

```java
// مثال توضيحي: هندسة باش يكون الكود مرن
public interface ApprovalStrategy {
    boolean isApproved(Request request);
}

public class SeniorManagerStrategy implements ApprovalStrategy {
    public boolean isApproved(Request request) {
        return request.getAmount() > 1000 && request.hasRole("SENIOR_MGR");
    }
}
```

## غلط شائع: التعقيد الزايد من الأول
بزاف ديال الناس كيغلطو فاش كيبغيو يتوقعو كاع السيناريوهات اللي ممكن يوقعو فالمستقبل قبل ما يبداو يكتبو حتى سطر ديال الكود. هادشي كيخليهم يحبسو (Analysis Paralysis). الحل هو 'البناء التدريجي': صاوب أبسط نسخة كتجاوب مع شروط القبول ديال دابا، ولكن خلي الكود نقي باش يكون ساهل تبدلو من بعد.

## تمرين تطبيقي
السيناريو: بغيتي تزيد ميزة 'التنبيهات' (Notifications) لتطبيق المشتريات.
السؤال: شنو هي طريقة 'الكودينغ' وشنو هي طريقة 'الهندسة' فهاد الحالة؟

**الجواب:** طريقة الكودينغ هي تكتب كود صيفط Email وسط الفنكشن ديال الموافقة. طريقة الهندسة هي تصاوب Notification Service بوحدها، باش تقدر تبدل من Email لـ SMS ولا Slack بلا ما تقيس الكود ديال الموافقة.
