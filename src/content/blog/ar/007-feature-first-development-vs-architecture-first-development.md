هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل راسك خدام على تطبيق ديال الشراء (procurement app). الشيف ديالك بغا بوتون ديال «طلب شراء» يكون واجد الجمعة. إلا دوزتي السيمانة كاملة غير كتصاوب في السكيم ديال لاباز دو دوني (database schema) وكتفكر في كاع الحالات اللي يقدروا يوقعوا من هنا لعام، غادي توصل للجمعة وما عندك والو باش توري. هذا هو الفخ ديال Architecture-First.

## الفخ ديال Architecture-First
هاد الطريقة كتعامل مع الديزاين ديال السيستيم بحال إلا هو شرط أساسي باش تبدا. الهدف هو تصاوب ساس «مثالي» قبل ما تكتب حتى سطر ديال الكود اللي كينفع الكليان. وخا كتبان هاد الطريقة آمنة، ولكن غالباً كتسالي بـ «over-engineering»، يعني كتصاوب شي حاجة معقدة بزاف لمشاكل اللي أصلاً ما كاينينش دابا.

## الطريقة ديال Feature-First
هنا كنركزو على ما يسمى بـ «Vertical Slice». بلاصت ما تصاوب كاع الطبقات ديال الداتا ومن بعد كاع الطبقات ديال السيرفيس، كتصاوب طريق وحدة من الواجهة (UI) حتى للداتا غير لواحد الخدمة محددة. مثلاً في تطبيق الشراء: الموظف كيدير الطلب → الطلب كيتسجل → كتطلع رسالة تأكيد. هنا كتحدد القواعد ديال البيزنس وشنو خاص يوقع بالضبط، وعاد كتصاوب غير الديزاين اللي محتاج باش تخرج ديك الخدمة.

## مثال تطبيقي: الموافقة على الطلب
في Feature-First، كنبداو بالنتيجة: «المدير خاصو يقدر يوافق على الطلب».

```java
// مثال بسيط: مركز غير على خدمة الموافقة
public class ApprovalService {
    public void approveRequest(Long requestId, Long managerId) {
        // 1. نتأكدو واش المدير عندو الحق يوافق
        // 2. نبدلو الحالة لـ 'APPROVED'
        // 3. نصيفطو خبر للمشتري (Buyer)
    }
}
```
النتيجة: البيزنس كيكون عندو خدمة خدامة دابا. والديزاين ديال السيستيم كيتطور شوية بشوية ملي كنزيدو خدمات أخرى بحال «الرفض» أو «مراقبة الميزانية».

## غلط شائع: «ما كاينش ديزاين»
بزاف ديال المطورين كيسحاب ليهم Feature-First كتعني «خدم بلا ديزاين». كيوليو يكتبو كود مرون غير باش يساليوا دغيا.
**التصحيح:** خدم بـ «Architecture Itérative». صاوب أبسط ديزاين اللي يخلي الخدمة تخدم، ولكن خليه نقي باش تقدر تبدلو (refactor) ملي تزيد الخدمة الجاية وتولي الأمور معقدة.

## تمرين تطبيقي
السيناريو: بغيتي تزيد خدمة «طلب المشتري» (Buyer Order). واش خاصك تصاوب «إطار عمل عام» (Generic Framework) لكل أنواع الطلبات، ولا تصاوب غير الطريق ديال طلب شراء واحد محدد؟

**الجواب:** صاوب الطريق ديال طلب شراء واحد محدد هو الأول (Feature-First). وملي يولي عندك 3 ديال الأنواع مختلفة من الطلبات، تما عاد جمع داكشي اللي كيتعاود في Framework واحد.
