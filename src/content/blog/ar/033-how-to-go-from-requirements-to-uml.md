تخيل جاو عندك بـ document فيه: 'الموظف خاصو يصيفط طلب شراء، ومن بعد الماناجير كيوافق عليه، وعاد الشاري (Buyer) كيدوز الكوموند'. إلا بديتي تكودي نيشان، تقدر تنسى حالات مهمة، بحال مثلا شنو يوقع إلا الماناجير رفض الطلب. هنا فين كيجي الدور ديال UML باش يربط بين داكشي اللي بغا الكليان وبين الكود.

## تحديد الشخوص (Actors) والأهداف
أول حاجة خاصك تخرج 'شكون' و 'شنو'. فالمثال ديالنا، actors هما: الموظف، الماناجير، والشاري. الأهداف ديالهم هي: يصيفط، يوافق، ويشري. هادشي كيرسموه فـ Use Case Diagram. هاد الرسمة ما كاتبينش الترتيب، ولكن كاتبين غير شكون كيدير شنو فالسستيم.

## رسم المسار ديال الخدمة (Business Flow)
ملي كتحدد الأهداف، خاصك ترسم المنطق (logic). راه ماشي أي flow هو UML، ولكن هو الساس. باش تبين القرارات، كنستعملو Activity Diagram. مثلا، مورا 'صيفط الطلب'، كدير واحد المعين ديال القرار: 'واش مقبول؟'. إلا كان آه، كيمشي عند الشاري؛ إلا كان لا، كيرجع عند الموظف باش يصححو.

## ترتيب التفاعلات (Interactions)
الـ Activity Diagram كيبين المنطق، ولكن Sequence Diagram كيبين الوقت وشكون المسؤول. هنا كنرسمو objects وكيفاش كيهضرو بيناتهم.

مثال:
1. `Requester` -> `RequestService`: `createRequest(details)`
2. `RequestService` -> `Database`: `save(request)`
3. `Manager` -> `RequestService`: `approveRequest(id)`

هادشي كيخليك تعرف بالضبط أنا class هي اللي غاتكلف بكل معلومة فكل لحظة.

## تحديد البنية (Structure)
فاللخر كنمشيو لـ Class Diagram. واحد الغلط كيديروه بزاف هو كيسحاب ليهم Class Diagram هو نفسو SQL table. ولكن الـ Class كيكون فيها حتى الـ behavior (الأفعال). مثلا class ديال `ProcurementRequest` خاص يكون فيها methods بحال `calculateTotal()` ماشي غير columns ديال data.

## غلط شائع: رسمة فيها كلشي
بزاف كيحاولوا يديروا كلشي فرسمة وحدة. إلا كان Sequence Diagram فيه 50 سهم، غايولي غير كيخربق. الحل هو تقسم السستيم لسيناريوهات صغيرة وواضحة.

## تمرين تطبيقي
**الوضعية:** واحد المستخدم بغا يبدل المود باس ديالو. خاصو يعطي المود باس القديم، والسستيم يتأكد منو عاد يخليه يدير واحد جديد.
**السؤال:** شنو هما جوج ديال UML diagrams اللي يصلحو باش نبينو 'منطق القرار' و 'التفاعل بين objects' فهاد الحالة؟

**الجواب:** Activity Diagram باش نبينو واش المود باس صحيح ولا لا (Yes/No)، و Sequence Diagram باش نبينو التفاعل بين User و PasswordController و UserAccount.
