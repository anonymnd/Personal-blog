هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

بزاف ديال المبتدئين كيصحاب ليهم بلي يلا تقطع الأنترنيت ولا طاح GitHub، مابقاوش قادرين يتبعو التغييرات لي دارو ف الكود ديالهم. هادشي كيوقع حيت كيخلطو بين الأداة لي كتحفظ التاريخ (Git) وبين السيت لي كيستضيف هاد التاريخ (GitHub).

## الفرق بين Git و GitHub
Git هو نظام (VCS) كيكون منصب عندك ف البي سي (local). هو لي كيسجل كاع التغييرات ف واحد الدوسي مخبي سميتو `.git`. أما GitHub، GitLab، ولا Bitbucket، هما غير خدمات ف السحاب (cloud) كيحطو فيهم نسخة من هاد المشروع باش تخدم مع ناس آخرين. يعني تقدر دير كاع داكشي ديال commits، branches، و merges بلا ما تحتاج تفتح المتصفح.

## كيفاش تخدم غير local
فاش كتخدم بلا سيرفور، الطريقة كتبقى هي هي. كبدا المشروع، كتزيد التغييرات، وكتسجلهم (commit) ف القاعدة ديال البيانات لي عندك ف الجهاز. مثلا، يلا كنتي كتصاوب تطبيق ديال المشتريات (procurement app)، تقدر تفتح branch جديدة باش تزيد خاصية `ManagerApproval` وتدمجها مع branch الرئيسية غير ف البي سي ديالك.

```bash
# بدا مشروع جديد local
git init procurement-app
# سجل التغييرات
git add . 
git commit -m "زدت المنطق ديال الموافقة ديال المدير"
```

## شنو غادي يخصك يلا ما خدمتيش بـ GitHub
واخا تقدر تبرمج بلا أنترنيت، غادي يخصك الجانب ديال التعاون. بلا GitHub، ماكاينش Pull Requests باش صحابك يراجعو الكود، وماكاينش backup يلا تفرمط ليك البي سي. ولكن بالنسبة لمشاريع شخصية ولا خدمة سرية، Git local كافي جداً.

## غلط شائع: كيسحاب ليهم push هي لي كتحفظ الكود
بزاف كيغلطو وكيصحاب ليهم بلي `git push` هي لي كتحفظ الخدمة. ف الحقيقة، `git commit` هي لي كتحفظ الخدمة ف التاريخ المحلي. `git push` غير كتصيفط داك التاريخ للسيرفور. يلا كنتي خدام بلا GitHub، ببساطة ما غاديش تحتاج تستعمل push.

## تمرين تطبيقي
جرب دير `git init` ف شي دوسي جديد، صاوب ملف، ودير ليه commit. من بعد، خدم `git log` باش تشوف واش التاريخ كاين واخا ماكاينش الأنترنيت.

**الجواب:** يلا بان ليك الـ hash والرسالة ديال الـ commit ف `git log`، راك قدرتي تخدم بلا GitHub.
