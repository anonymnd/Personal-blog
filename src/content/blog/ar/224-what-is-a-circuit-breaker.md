هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل معايا خدام على تطبيق ديال المشتريات (procurement app)، فين الموظف كيصيفط طلب شراء، والسيسطيم خاصو يعيط لواحد الـ API خارجية باش يحسب الضريبة. واحد النهار، هاد الـ API ديال الضريبة طاحت ولا ولات ثقيلة بزاف. التطبيق ديالك كيبقى يصيفط الطلبات، وبما أن كل طلب كيتسنى الـ timeout، الـ threads ديال السيرفر كيعمرو. فالاخير، التطبيق كامل كيتبلوكا وكيطيح، وخا المشكل كان غير فالسيرفيس ديال الضريبة. هادشي كيتسمى cascading failure.

## كيفاش كيخدم هاد الميكانيزم

الـ Circuit Breaker كيخدم بحال واحد الوسيط بين التطبيق ديالك والسيرفيس اللي بعيد. كيبقى حاضي الأخطاء وكيتحول بين 3 ديال الحالات:

1. **Closed (مسدود)**: الطلبات كيدوزو عادي. الـ breaker كيحسب شحال من مرة وقع خطأ. إلا فات واحد العدد محدد، كيتحول لـ Open.
2. **Open (محلول)**: هنا الـ breaker كيقطع الطريق وكيرجع خطأ ديك الساعة (fail-fast) بلا ما يحاول يعيط للسيرفيس. هكا كنعطيو الوقت للسيرفيس اللي طايح باش يرجع يخدم.
3. **Half-Open (نص محلول)**: مورا واحد الوقت، الـ breaker كيخلي يدوزو شي طلبات قليلة باش يتيستي. إلا نجحو، كيرجع Closed، وإلا فشلو، كيرجع Open.

## مثال تطبيقي: الموافقة على الطلب

فالتطبيق ديالنا، ملي المدير (Manager) كيوافق على طلب، السيسطيم كيعيط لسيرفيس ديال التنبيهات (Notification Service). إلا كان هاد السيرفيس ثقيل:

- **السيناريو**: وقعو 5 ديال الـ timeouts متابعين.
- **النتيجة**: السيركوي كيولي **Open**.
- **شنو كيوقع**: لمدة 30 ثانية، أي مدير ورك على "Approve" غادي تطلع ليه ميساج: "سيرفيس التنبيهات ما خدامش، الموافقة تسجلات فالسيسطيم". التطبيق ما كيبقاش يتسنى ومكيتبلوكاوش الـ threads.

## غلط شائع: خلط بينو وبين الـ Retry

بزاف كيغلطو وكيديرو Retry (إعادة المحاولة) بلاصة الـ Circuit Breaker. الـ Retry خطر ملي كيكون السيرفيس مضغوط حيت كتزيد تزيد عليه الضغط (كتسمى retry storm). الـ Circuit Breaker كيدير العكس: كيقطع التواصل كليا حتى يرجع السيرفيس صحيح.

## مثال ديال الكود

باستعمال Resilience4j فبيئة Jakarta EE:

```java
@CircuitBreaker(name = "taxService", fallbackMethod = "calculateTaxFallback")
public BigDecimal getTax(Request request) {
    return taxClient.callRemoteApi(request);
}

public BigDecimal calculateTaxFallback(Request request, Throwable t) {
    return BigDecimal.ZERO; // قيمة افتراضية باش السيسطيم ما يوقفش
}
```

## تمرين تطبيقي

**سؤال**: إلا كان السيركوي فالحالة ديال 'Open' وجات طلبية جديدة، واش التطبيق غادي يحاول يتصل بالسيرفر اللي بعيد؟

**الجواب**: لا، غادي يرجع خطأ مباشرة (fail-fast) باش يحمي السيسطيم والسيرفيس اللي طايح.
