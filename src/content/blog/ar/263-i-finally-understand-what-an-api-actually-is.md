هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

بزاف ديال الوقت كنت كنصحاب بلي API هي غير ديك الـ URL فين كاينين المعلومات. ما كنتش كنشوف الفرق بين الداتا (data) وبين الواجهة (interface). ولكن فهمت دابا بلي API هي بحال واحد « العقد » (contract) بين جوج ديال الأنظمة.

## مثال ديال العقد
الـ API ماشي هي السوفتوير راسو وماشي هي لاباز دو دوني. هي اتفاقية. تخيل معايا تطبيق ديال المشتريات (procurement app) فين الموظف كيطلب بي سي جديد. هاد الموظف ما محتاجش يعرف كيفاش المدير كيوافق على الطلب، ولا كيفاش السيستيم ديال الشراء خدام. خاصو غير يعرف « المينيو » ديال الحوايج اللي يقدر يطلبهم.

## كيفاش كتخدم هاد العملية
الـ API كتخدم بحال وسيط. كتعطينا واحد القائمة ديال الطلبات اللي يقدر يديرها الـ client وكتقول لينا كيفاش غادي يكون الجواب. فـ REST API، هادشي كيكون غالباً بـ HTTP methods. الـ client كيصيفط طلب لواحد الـ endpoint، والـ API كتأكد بلي الطلب صحيح عاد كتدوزو للخدمة الداخلية ديال التطبيق.

## مثال تطبيقي: طلب شراء
تخيل سيستيم ديال المشتريات. باش تصيفط طلب، الـ client كيصيفط POST request لـ `/api/requests` بهاد الشكل:

```json
{
  "item": "MacBook Pro",
  "quantity": 1,
  "reason": "Development work"
}
```

الـ API كتاخد هاد المعلومات، كتشوف واش `item` عامر، ومن بعد كترجع `201 Created` مع واحد الـ ID ديال الطلب. الموظف هنا ما قاصش لاباز دو دوني، تعامل غير مع الـ API.

## غلط شائع: الخلط بين API و Endpoint
بزاف ديال الناس كيقولو « راني كنعيط لـ API » وهوما كيقصدو غير URL وحدة. ديك الـ URL كتسمى **endpoint**، وهي غير باب واحد من بيبان الـ API. الـ API هي السيستيم كامل ديال البيبان، والقواعد ديال شكون يدخل، واللغة اللي كيهضرو بيها لداخل.

## تمرين تطبيقي
إلا كان عندنا endpoint سميتو `GET /api/requests/{id}`، شنو الـ API كتسنى من الـ client وشنو غادي ترجع ليه؟

**الجواب:** الـ API كتسنى ID ديال طلب معين فـ الـ URL. وغادي ترجع ليه المعلومات ديال داك الطلب (مثلاً: الحالة، السلعة، التاريخ) على شكل JSON.
