هاد الأمثلة غير باش نفهمو الفكرة؛ الإعدادات ديال التطبيق وبعض التعريفات المساعدة ممكن ما يكونوش مكتوبين.

تخيل معايا تطبيق ديال الشراء (procurement app) فين الموظف كيصيفط طلب شراء. هاد الـ Request Service خاصو يعيط لـ Inventory Service باش يشوف واش السلعة كاينة. إلا كان الـ Inventory Service تقيل ولا طاح، الـ Request Service غايبقى يصيفط طلبات ويبقى يتسنى (timeout)، وهادشي غايخلي الـ threads ديالو يتعمروا. فالاخير، السيستيم كامل غايتبلوكا، حتى دوك البلايص اللي ما محتاجينش الـ inventory. هادشي هو اللي كنسميوه cascading failure.

## كيفاش كيوقع هاد المشكل
فالسيستيمات الموزعة، مشكل صغير فخدمة وحدة يقدر يطيح كلشي بحال الدومينو. إلا ما كانش Circuit Breaker، الكليان غايبقى يحاول يعيط لواحد السيرفيس اللي ديجا طايح. هادشي كيزيد يضغط على السيرفيس اللي مريض ومكيخليهش يرجع يخدم، وفنفس الوقت كيضيع الموارد ديال السيرفيس اللي كيعيط ليه.

## كيفاش كيخدم الـ Circuit Breaker
هاد الـ pattern كيخدم بحال الديجونكتور ديال الضو فالدار، وعندو 3 ديال الحالات:
1. **Closed (مسدود)**: الطلبات كيدوزو عادي، والسيستيم كيحسب شحال من مرة وقع فشل.
2. **Open (محلول)**: ملي كيوصل عدد الفشل لواحد الحد، الديجونكتور "كيطير". أي طلب جديد كيرجع فشل ديك الساعة بلا ما يحاول يعيط للريزو.
3. **Half-Open (نص محلول)**: من بعد واحد الوقت، السيستيم كيخلي يدوزو شي طلبات قليلة باش يشوف واش السيرفيس رجع خدام. إلا نجحو، كيرجع Closed، وإلا فشلو كيرجع Open.

## مثال تطبيقي: الموافقة على الطلب
المدير (Manager) كيوافق على طلب. الـ Approval Service كيعيط لـ Notification Service باش يصيفط إيميل.

```java
// مثال توضيحي لـ circuit breaker
public Response approveRequest(Long requestId) {
    return circuitBreaker.execute(() -> {
        // عيط لـ Notification Service (L7 HTTP call)
        return notificationClient.sendEmail(requestId);
    }, fallback() -> {
        // رجع جواب مؤقت باش السيستيم ميتبلوكاش
        return Response.accepted("الموافقة تسجلات، الإيميل غايوصل من بعد");
    });
}
```
**النتيجة**: إلا كان الـ Notification Service طايح، المدير غايشوف "الموافقة تسجلات" فالبلاصة، بلا ما يتسنى 30 ثانية وتطلع ليه Error 504.

## غلط شائع: تخلط بينو وبين الـ Retries
بزاف كيغلطو وكيستعملو الـ retries (إعادة المحاولة) بلاصة الـ circuit breaker. الـ retries خطرين ملي كيكون السيرفيس مضغوط، حيت كتولي بحال إلا كتهجم على راسك (DoS attack). الـ circuit breaker *كيحبس* الطلبات، بينما الـ retry *كيزيدهم*.

## تمرين تطبيقي
**السيناريو**: عندك سيستيم فيه نسبة فشل ديال 50%. الـ circuit breaker ديالك كيتحل (Open) إلا وقعو 5 ديال الفشل متابعين. واش الـ circuit غايتحل إلا كان الفشل متبادل (فشل، نجاح، فشل، نجاح)؟

**الجواب**: لا. حيت الفشل ماشي متابع (consecutive)، يعني الـ counter مكيصلش للحد المطلوب، والـ circuit كيبقى Closed.
