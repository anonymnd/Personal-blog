تخيل عندك تطبيق ديال الشراء (procurement app) فين الموظفين كيصيفطو طلبات. فالبداية، كان عندك سيرفور واحد هو لي هاز كلشي. ولكن مع الوقت، الشركة كبرات وولا كيجيو مئات الطلبات فدقة وحدة، السيرفور مابقاش قادر يصبر وكيطيح. زدتي 3 ديال السيرفورات خرين، ولكن دابا عندك مشكل جديد: كيفاش غاتعرف كل طلب فين يمشي؟

## كيفاش كيخدم هادشي
الـ Load Balancer كيخدم بحال شي «عساس» (reverse proxy) كيكون واقف بين الكليان والسيرفورات. عوض ما الكليان يتكونيكطا نيشان للسيرفور، كيمشي عند الـ load balancer، وهو لي كيقرر فين يصيفط الطلب على حساب واحد الخوارزمية (algorithm). هادشي كيخلي حتى شي سيرفور ما يتزير بزاف، وإلا طاح شي واحد، الترافيك كيمشي للسيرفورات لي باقيين خدامين.

## الفرق بين L4 و L7
كاينين جوج أنواع ديال الـ load balancing على حساب الطبقة (layer) لي خدام فيها:
- **Layer 4 (Transport):** سريع بزاف حيت كيشوف غير الـ IP والـ Port. ماكيهمش شنو كاين وسط الداتا.
- **Layer 7 (Application):** ذكي كتر، حيت كيقدر يشوف الـ HTTP headers والـ cookies. مثلاً، يقدر يصيفط الطلبات ديال `/orders` لسيرفورات بوحدهم، والطلبات ديال `/approvals` لسيرفورات خرين.

## طرق توزيع الترافيك
الاختيار ديال الطريقة كيعتمد على نوع الترافيك لي عندك:

| الطريقة | كيفاش كتخدم | فوقاش كنستعملوها |
| :--- | :--- | :--- |
| Round Robin | بالترتيب واحد بواحد | سيرفورات عندهم نفس القوة |
| Least Connections | للسيرفور لي عندو أقل ضغط | كونيكسيو طويلة (WebSockets) |
| IP Hash | على حساب الـ IP ديال الكليان | باش يبقى الكليان مع نفس السيرفور |

## مثال تطبيقي: تطبيق الشراء
نفترضو عندنا 3 ديال السيرفورات (S1, S2, S3) وخدامين بـ Round Robin:
1. الموظف A صيفط طلب → الـ LB صيفطو لـ S1.
2. المدير B حل لوحة التحكم → الـ LB صيفطو لـ S2.
3. المشتري C أكد الطلبية → الـ LB صيفطو لـ S3.
4. الموظف D صيفط طلب → الـ LB كيرجع لـ S1.

النتيجة: الترافيك مقسوم بالتساوي وماكاينش سيرفور لي غايتخنق.

## غلط شائع: مشكل الـ State
بزاف ديال المطورين كينساو باللي الـ load balancer كيخلي السيستيم stateless. إلا كان المستخدم كونيكطا فـ S1، والطلب الجاي مشى لـ S2، هاد S2 ماغايعرفوش شكون هو.
**الحل:** خاصك تستعمل شي حاجة خارجية فين تخزن المعلومات (بحال Redis) أو تخدم بـ "Sticky Sessions" باش المستخدم يبقى ديما مع نفس السيرفور.

## تمرين تطبيقي
إلا كانو عندك سيرفورات مختلفين بزاف فـ القوة (CPU و RAM)، علاش Round Robin ماشي اختيار مزيان؟

**الجواب:** حيت Round Robin كيتعامل مع كلشي بحال بحال. السيرفور الضعيف غايتزير بزاف، والسيرفور القوي غايبقى خاوي.
