Imagine you are building a procurement app. A user tries to access the `/approve-request` endpoint, and the server returns an error. If you use 401 and 403 interchangeably, your frontend won't know whether to redirect the user to the login page or show an 'Access Denied' warning. This confusion leads to poor user experience and security gaps.

## The Core Difference
HTTP 401 (Unauthorized) actually means 'Unauthenticated'. It indicates that the server does not know who the user is. The request lacks valid credentials or the provided token has expired. In contrast, HTTP 403 (Forbidden) means the server knows exactly who you are, but you simply do not have the permission to access that specific resource.

## How it Works in Practice
When a request hits the server, the security filter first checks for a valid identity (Authentication). If the JWT is missing or the signature is invalid, it returns a 401. Once the identity is confirmed, the server checks the user's roles or permissions (Authorization). If a 'Requester' tries to access a 'Manager' only function, the server returns a 403.

## Worked Example: Procurement Workflow
Consider a request to `POST /orders/approve`:

1. **Scenario A**: The user sends the request without a Bearer token. 
   - **Outcome**: `401 Unauthorized`. The server says: "I don't know who you are; please log in."
2. **Scenario B**: The user is logged in as a `REQUESTER` and sends a valid token. 
   - **Outcome**: `403 Forbidden`. The server says: "I know you are a Requester, but only Managers can approve orders."

## Common Mistake: The Generic Error
A common error is returning 403 for everything security-related. If a token expires and you return 403, the frontend might show "You don't have permission" instead of triggering the refresh token flow or redirecting to login. Always use 401 for identity issues and 403 for permission issues.

## Practical Exercise
Which status code should be returned if a user provides a valid JWT but tries to delete a procurement request that belongs to another department?

**Answer**: 403 Forbidden. The user is authenticated, but they are not authorized to modify that specific resource.
